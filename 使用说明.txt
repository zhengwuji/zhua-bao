========================================
  抓包豆 Creator v1  (单文件免安装版)
========================================

【版本号说明】
  本程序对外版本号用递增式简写：v1 → v2 → v3 → …
  当前 v1 = 参照 Fatbeans Creater V1.0.8 更新内容的落地版本。
  标题栏显示：抓包豆 Creator (配豆创器) v1 [全能模式]
  发版时只需改源码 Zhuabao.Core\AppInfo.cs 里的 Version 常量。

【本版（v1）更新内容】—— 对应 Fatbeans Creater V1.0.8
  ★ 新增 转发器：条件匹配的 TCP 封包「旁路」转发到你自己的 API 地址，不影响正常流量
    菜单 代理(P) → 转发器(旁路转发 TCP/UDP)...
    见下面【转发器（旁路转发到自己的 API）】

  ★ 自定义大模型接口新增 Anthropic 兼容模式
    菜单 AI智能助手(I) → 自定义大模型接口...
    支持 OpenAI 兼容 与 Anthropic 兼容 两种协议，可「测试连接」并在发送前预览请求 JSON
    选中一条封包后 → 「用大模型分析当前封包」，直接把会话交给模型分析

  ★ 修改器「改响应头」中可直接改状态码
    修改器里把「目标」选 :status（伪头名），「值」填 404 或 "404 Not Found"
    也可以填区间如 200-299（在区间内随机取码）

  ★ 修复：右键「重发此请求」不再覆盖原封包
    重发现在生成一条**新的副本会话**（备注为「重发副本 ← 原会话ID」），
    原封包连同原始字节保持不变，随时可以对照

  ★ 修复：修改器规则的「次数限制」不再失效
    已用次数由程序内部按规则内容记住，配置保存/重开面板都不会清零；
    面板里新增「限次」「次数」「已用」三列，以及「重置选中规则次数 / 全部重置次数」

  ★ 优化：工具箱解码器面板新增「专用解码器 GitHub 示例代码链接」
    下拉选择 AES / DES / RC4 / XXTEA / XOR / Protobuf / MessagePack / BSON /
    FlatBuffers / AMF0-AMF3 / 插件框架说明，点链接直达示例代码

【运行环境】
  Windows 10 / 11 64 位
  自包含单文件，无需安装 .NET 运行时，双击 ZhuabaoCreater.exe 即可。

【快速开始】
  1. 双击 ZhuabaoCreater.exe
  2. 点工具栏 ▶ 启动(F5)     → 代理监听 127.0.0.1:8899
     ★ 启动时自动接管 Windows 系统代理，Edge/Chrome 免配置直接抓包
     （要让手机 / Mac 也抓，见下面【手机 / Mac / 其他电脑抓包（局域网）】）
  3. 打开任意网页即可看到封包（列表空时会显示等待提示）
  4. ★抓 HTTPS 要装根证书：
     点启动后会弹提示选『是』→ Windows 再弹【安全警告】→ 点『是』即可
     也可手动：菜单 证书(C) → 查看/安装根证书状态
     不装证书时 HTTPS 站点会报证书错误（HTTP 站点不受影响）
  5. 点 ■ 关闭(F5) 或退出程序，系统代理自动恢复原设置，不影响上网

【快捷键】
  F5  启动 / 关闭代理
  F6  停止代理
  F7  清空列表并重新开始
  F4  打开配置（改监听端口等）

【系统代理接管说明】
  · 默认开启：菜单 代理(P) → 「启动时接管系统代理」可关
  · 菜单里还有「立即接管」「恢复系统代理原设置」手动操作
  · 内网地址 (10.x / 172.16-31 / 192.168) 自动直连不走代理
  · Firefox 用独立代理体系，需手动设置 127.0.0.1:8899
  · 崩溃自愈：程序异常退出（崩溃/被强杀）会把原代理设置记在
    sysproxy-crash.mark，下次启动时自动还原，不会让你一直断网
  · 万一仍然断网：菜单 代理(P) → 恢复系统代理原设置，
    或 Windows 设置 → 网络和Internet → 代理 → 关闭"使用代理服务器"

【只抓指定网卡的包】
  菜单 代理(P) → 「选择抓包网卡...」
  · 选「全部网卡（不限制）」= 默认，抓所有流量
  · 选中某块网卡（如 192.168.1.100 — 以太网）后，上游出站连接会绑定
    该网卡 IP：只有走这块网卡出去的请求才会被转发和抓取
  · 本机/回环地址（127.0.0.1、localhost、本机 IP）不受限制，本地调试
    服务不会被切断
  · 设置对之后的新连接立即生效，无需重启代理
  · 日志里会打印「出站绑定网卡 x.x.x.x → host:port」便于确认

【抓包列表】
  · 顶部 Tab 过滤：全部/发送/接收/TCP/UDP/HTTP/HTTPS/WS/GET/POST/正常放行/已拦截
  · 底部筛选条：按「内容」关键字或「进程」名过滤
  · 右键封包：重发 / 复制 URL / 复制请求头 / 保存为文件 / 删除

【封包详情与改包（点中列表任意一条即可）】
  右侧「封包」页会显示该会话的全部内容，分 6 个页签：
    · 预览     响应网页直接渲染（可切「源码」看 HTML）
    · 原始报文 请求 + 响应的完整原文
    · 请求     请求头（可直接编辑） + 请求体
    · 响应     响应头（可直接编辑） + 响应体
    · 修改     大编辑框 + 多种修改方式：
        ① 直接改文本
        ② 查看方式切换：文本 / JSON美化 / Base64 / Hex
        ③ 「内容按 Base64 解码/编码」勾选框
        ④ 「✔ 应用到会话」把改动写回该会话
        ⑤ 「⬆ 按此内容重发」改完立即重发验证
        ⑥ 「存为改包规则」把"原内容→新内容"保存成全局规则，
           之后匹配的流量自动替换
        ⑦ 「存为重定向」把该 URL 存成重定向规则

【右侧功能面板】
  HTTP发送器  编辑原始请求重发，可循环 1/10/100/1000 次（重发生成副本，不覆盖原封包）
  回复器      请求匹配关键字时返回固定响应（规则表）
  取值器      从响应表单/JSON/头/Cookie 正则提取变量
  重定向      正则映射 URL，如 api\.test\.com → api.prod.com
  封包对比    载入最近两条会话逐行比对
  工具箱      Base64 / Hex / URL 编解码、时间戳转换、MD5
              + 专用解码器 GitHub 示例代码链接（AES/DES/RC4/XXTEA/XOR/Protobuf/...）

【转发器（旁路转发到自己的 API）】
  菜单 代理(P) → 转发器(旁路转发 TCP/UDP)...
  · 它做什么：把命中规则的封包，用 HTTP POST（JSON）复制一份发到你自己填的地址。
  · 旁路 = 不等响应、不阻塞、不影响原通讯，也不影响拦截器 / 修改器 / WebHook。
    它只读不写：不修改也不拦截封包。
  · 和 WebHook 的区别：WebHook 是串行的（会等你的接口返回，超时会卡抓包），转发器是旁路的。
  三步用起来：
  ① 全局配置：填「转发目标地址」（例 http://127.0.0.1:9000/hook），
     设并发 Worker（1~10）、队列上限、超时、单包上限 → 保存配置
  ② 规则表：加规则，填匹配条件（协议 / 源IP / 目的IP / 端口起-止 / 长度起-止 / 内容）
     和排除条件（任一命中即不转发，优先级更高）
  ③ 勾「启用转发器」→ 保存配置（代理在跑时立即生效）
  规则填写说明：
  · 匹配条件要**同时满足**所填的每一项；整行匹配条件全空 = 转发全部 TCP/UDP
  · IP 支持 192.168.* 前缀写法，也支持逗号分隔多值：10.0.0.1, 104.160.*
  · 端口/长度支持 "起-止"（如 5000-5100），只填一个数字 = 精确匹配
  · 内容列前面加 HEX: 可按十六进制字节匹配，例：HEX:68 65 6C 6C 6F
  · 队列满时会**丢弃最旧的封包**（底部统计能看到丢弃数），请合理设置队列上限
  · 「发送测试封包」可以投一条测试包验证目标地址通不通
  转发过去的 JSON 长这样（字段与 Fatbeans 转发器一致，另附 Direction 区分发送/接收）：
    {"Protocol":"TCP","SrcIP":"127.0.0.1","SrcPort":0,"DstIP":"api.example.com",
     "DstPort":443,"PID":0,"ProcessName":"chrome","DataLength":512,
     "DataBase64":"UE9TVC...","HexData":"50 4F 53 54 ...","Timestamp":1759536000000,
     "RuleID":"xxxx-...","RuleName":"登录包","Direction":"Send"}
  接收端不需要返回任何内容，转发器不读响应。
  ★ 说明：本复刻版的抓包引擎是 HTTP/HTTPS 代理（没有网卡驱动），
    所以转发的是代理看到的 HTTP/HTTPS/WS 字节按方向切成的封包（请求=Send、响应=Receive）。

【自定义大模型接口（含 Anthropic 兼容模式）】
  菜单 AI智能助手(I) → 自定义大模型接口...
  · 接口模式两种：
      OpenAI 兼容    → POST {BaseUrl}/v1/chat/completions，Authorization: Bearer <key>
      Anthropic 兼容 → POST {BaseUrl}/v1/messages，x-api-key + anthropic-version: 2023-06-01
  · BaseUrl 留空会用官方默认（api.openai.com / api.anthropic.com）
  · 模型名示例：claude-3-5-sonnet-latest（Anthropic） / gpt-4o-mini（OpenAI）
  · 「请求预览」把即将发出的 JSON 和鉴权头直接显示出来，方便离线核对
  · 「测试连接」会真的发一次极小请求，验证 key / 网络 / 模型名是否可用
  · 选中封包后 → 菜单 AI智能助手(I) → 用大模型分析当前封包（请求/响应各截 6000 字符）

【改状态码（修改器）】
  · 「目标」下拉里除了 请求头/请求体/响应头/响应体/状态行/URL，还有一个 :status
  · 选 :status →「值」填目标状态码：
      404                → 只改码，原因短语自动用标准短语（Not Found）
      403 Forbidden      → 码 + 自定义原因短语
      200-299            → 在这个区间里随机取一个码
  · 也可以直接用「状态行」目标，效果相同
  · 非 :status 的响应头规则行为不变，老规则文件无需修改

【次数限制（修改器）】
  · 规则表新增三列：限次（勾选框）/ 次数（上限）/ 已用（当前已生效次数）
  · 勾上「限次」并把「次数」设为 N，这条规则最多生效 N 次，之后自动跳过
  · 已用次数由程序按规则内容记住：保存配置、关掉重开面板都不会清零（这是 v1 的修复点）
  · 改了规则的任何内容（方向/目标/匹配/类型/值/备注）＝一条新规则，次数从 0 重新算
  · 想手动清零：「重置选中规则次数」或「全部重置次数」
  · 重启程序后计数从 0 开始

【重发不会覆盖原封包（v1 修复）】
  · 右键 「重发此请求」 或 详情页 「按此内容重发」 都生成一条**新的副本会话**
  · 副本的备注会写成「重发副本 ← 原会话ID」，在列表里一眼能认出来
  · 原封包的内容与原始字节完全不变，随时可以对照、可以再次重发
  · 批量重发（10/100/1000 次）时，界面上最多只显示前 20 条副本，其余仍会落盘

【专用解码器 GitHub 示例代码（工具箱）】
  · 右侧面板 → ⚙ 工具箱 → 上方「专用解码器示例代码」区
  · 下拉选 AES / DES / RC4 / XXTEA / XOR / Protobuf / MessagePack / BSON /
    FlatBuffers / AMF0-AMF3 / 插件框架说明
  · 右侧显示对应示例地址与参数提示（Key/IV 格式、模式、偏移等）
  · 点链接或「打开示例代码」按钮 → 用系统默认浏览器打开
  · 对应 Fatbeans 的 Plugins\Codecs 里的内置解码器（AesDecoderPlugin / Rc4DecoderPlugin 等）

【手机 / Mac / 其他电脑抓包（局域网）】
  默认只听 127.0.0.1，只有本机能用。要让手机/Mac 抓，走这三步：
  1. 菜单 代理(P) → 「手机 / Mac 抓包向导（局域网）...」
     勾选「允许局域网设备连接」→ 代理改为监听 0.0.0.0（任何网卡都能连）
     点「放行防火墙」（会弹 UAC，放行入站 TCP 8899；仅专用/域网络）
  2. 看向导里的「本机局域网地址」，例如 192.168.1.100:8899
     对端设备（手机/Mac/另一台电脑）与本机必须在同一个局域网，且能 ping 通
  3. 对端装根证书（不装则 HTTPS 报证书错误）：
     · 菜单 证书(C) → 「导出通用根证书 .crt」 → 拷到对端安装
     · iPhone/iPad 更省事：菜单 证书(C) → 「导出 iOS 描述文件 .mobileconfig」，
       传到手机点安装 → 设置 → 通用 → VPN与设备管理 → 安装 →
       ★必须再去 设置 → 通用 → 关于本机 → 证书信任设置 → 打开「完全信任」
     · macOS：双击 .crt → 钥匙串访问 → 系统 → 设为「始终信任」
       （Firefox 有独立信任库，需另外导入一次）
     · Android：设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书
  4. 对端设置代理（手动，填本机局域网地址）：
     · Windows：设置 → 网络和Internet → 代理 → 手动设置 → 地址+端口
     · macOS：系统设置 → 网络 → 详细信息 → 代理 → 网页/安全网页代理
     · iOS：设置 → 无线局域网 → 点当前 Wi-Fi 的 ⓘ → 配置代理 → 手动
     · Android：WLAN → 长按网络 → 修改 → 高级 → 代理 → 手动
  ★ 向导里「复制步骤」可把上面全部内容拷成文本，方便照做。
  ★ 局域网模式没有账号密码：同网段任何设备都能用本代理，抓完请取消勾选切回
    「仅本机」，或直接关掉代理。
  ★ Android 7 以上，App 默认不信任用户安装的证书（只有浏览器类走系统信任库的
    才生效）；自带信任策略或做了证书固定(App 内置 CA)的 App 抓不到，需要在
    App 层放行，属于系统机制不是本程序的问题。
  ★ QUIC / HTTP/3 流量不走 HTTP 代理，抓不到属正常现象（可在浏览器关闭 QUIC）。

【出问题怎么查】

【注意事项】
  · 根证书用于解密 HTTPS，仅本机使用。不装也能抓 HTTP，只是 HTTPS 会报证书错误。
    安装时 Windows 的【安全警告】是系统保护机制，点『是』即可，属正常流程。
  · 程序换了目录或删了 Config 目录会重新生成一张 CA，需要重新安装一次根证书。
  · 端口 8899 被占用时，用 F4 配置换成其他端口（如 8888）。
  · 程序带单实例保护，重复双击会提示「已在运行」，不会冲突报错。
  · 卸载：直接删除整个文件夹即可；证书可用 菜单 证书(C) → 卸载根证书 移除。

【命令行模式】
  ZhuabaoCreater.exe --selftest     核心自检（52 项，含 v1 转发器/大模型/次数限制/改状态码/重发副本/MCP 服务）
  ZhuabaoCreater.exe --proxytest    系统代理接管自检
  ZhuabaoCreater.exe --enginetest   端到端自检：本机 HTTP + 局域网 HTTPS 解密 + 转发器接线
  ZhuabaoCreater.exe --uitest       自动化 UI 测试：自动把每个功能点一遍（约 30 秒）
                                    报告写在 uitest-report.txt，退出码 0 = 全部通过
  ZhuabaoCreater.exe --autostart    启动后自动开启代理

【自动化 UI 测试会做什么】
  打开主窗口后自动依次点击：全部菜单项、工具栏按钮、左右页签、列表右键菜单、
  封包详情的每个页签与按钮、以及每个对话框内部的控件（转发器与自定义大模型面板也已纳入）。
  · 弹出的对话框会被自动关掉（等同点「取消」），不会卡住
  · 会弹 UAC 的「放行防火墙」、会弹 Windows【安全警告】的「安装根证书 / 卸载根证书」，
    以及会真的对外发请求或拉起浏览器的「发送测试封包 / 测试连接 / 打开示例代码」，自动跳过并在报告里写明原因
  · 测试结束会还原系统代理注册表快照，并清理测试期间装上的临时证书
  · 想复现问题看 uitest-report.txt（逐条点击记录）和 logs\zhuabao-年月日.log
